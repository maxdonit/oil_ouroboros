# reports-base Specification

## Purpose
База отчётов агентств — первичный источник агента (уровень 0): выпуски EIA STEO, OPEC MOMR и IEA OMR (публичная
часть), наблюдатель, который сам скачивает новые выпуски, ручная загрузка, разбор и индекс фрагментов в Qdrant и
гибридный поиск по нему. Возможность отвечает за то, какие выпуски есть в базе, как они туда попадают и как по ним
находятся кандидаты для ответа; план запросов и LLM-отбор фрагментов — спека `research-tool`.

## Requirements

### Requirement: Состав базы выпусков
Список выпусков (`reports/editions.py: load`) SHALL объединять курируемый `data/reports/catalog.yaml` (файлы в git)
и каталог выпусков `<REPORTS_AUTO_DIR>/catalog.yaml` (пусто — `var/reports`; в Docker — общий том tools и encoder). Id выпуска — `{org}-{report}-{edition}` в нижнем регистре, `edition` — `ГГГГ-ММ`. При
одинаковом id главнее курируемая запись, но запись без файла уступает записи с файлом. Агентства для фильтра поиска
и планировщика (`orgs()`) — только выпуски с файлом на месте.

#### Scenario: База сразу после клонирования
- **WHEN** сервис запущен из репозитория без сети
- **THEN** в базе 6 выпусков: EIA STEO, OPEC MOMR и IEA OMR за 2026-09 и 2026-10, id вида `opec-momr-2026-10`

#### Scenario: Запись без файла уступает скачанной
- **WHEN** в `data/reports/catalog.yaml` есть `opec-momr-2026-11` без файла, а в каталоге выпусков — та же запись с файлом
- **THEN** `load()` возвращает запись каталога выпусков

#### Scenario: Новое агентство без правки кода
- **WHEN** в `data/reports/` добавлены файл и запись каталога с `org: XYZ`
- **THEN** `orgs()` содержит `XYZ`, пока файл на месте
- **AND** `GET /api/reports` сервиса инструментов отдаёт эту запись со всеми полями

### Requirement: Правила серий и график выпусков
Наблюдатель SHALL брать правила серий из `config/current/reports.yaml` (`sources`) и держать в базе последние
`lookback` (1–12, по умолчанию 2) месячных выпусков каждой серии, начиная с текущего месяца (`targets`). Выпуск ещё
не вышел, если его дата по `schedule` позже сегодняшней, а без графика — если это выпуск текущего месяца и сегодня
раньше `earliest_day` (1–28, по умолчанию 1).

#### Scenario: Текущие правила
- **WHEN** читается `config/current/reports.yaml`
- **THEN** OPEC MOMR — `kind: pdf`, `schedule` на 2026 год, `latest_url: https://momr.opec.org/pdf-download/`
- **AND** EIA STEO — `pdf`, `earliest_day: 6`, ссылка `https://www.eia.gov/outlooks/steo/archives/{mon}{yy}.pdf`; IEA OMR — `html`, `earliest_day: 11`; у всех `lookback: 2`

#### Scenario: Выпуски, которые должны быть в базе
- **WHEN** сегодня 2026-01-05, серия OPEC MOMR
- **THEN** `targets` — `["2026-01", "2025-12"]`

#### Scenario: Ближайший выпуск по графику и без него
- **WHEN** сегодня 2026-10-20
- **THEN** `next_release` OPEC MOMR — `("2026-11", "2026-11-11")`
- **AND** для IEA OMR на 2026-11-03 — `("2026-11", "не раньше 2026-11-11")`, на 2026-12-20 — `("2027-01", "не раньше 2027-01-11")`

#### Scenario: Подстановки в ссылках
- **WHEN** ссылка строится для выпуска 2026-09
- **THEN** `{yyyy}` — 2026, `{yy}` — 26, `{mm}` — 09, `{month}` — september, `{mon}` — sep, `{Month}` — September

### Requirement: Скачивание без обхода защиты от ботов
Наблюдатель SHALL ходить на сайты агентств через `net.outbound` (OUTBOUND_PROXY, CA_BUNDLE; таймаут 120 с, с
редиректами) с заголовком `User-Agent: oil-ouroboros-report-watch/1.0 (+https://github.com/maxdonit/oil_ouroboros)`
и MUST NOT обходить проверку от ботов: такой ответ получает статус `blocked`, выпуск загружают вручную. Итог выпуска
по всем его ссылкам — первый из `blocked`, `wrong_edition`, `error`, иначе `not_found`.

#### Scenario: Сайт за Cloudflare
- **WHEN** ссылка отвечает 403 с `cf-mitigated: challenge` или 503 со строкой «Just a moment» в первых 6000 байт
- **THEN** итог выпуска — `blocked` с пояснением «сайт закрыт проверкой от ботов — загрузите PDF вручную»
- **AND** файл в каталог выпусков не записывается

#### Scenario: Прочие ответы
- **WHEN** ссылка отвечает 403, 404 или 410 без признаков проверки от ботов
- **THEN** статус ссылки — `not_found`
- **AND** иной код, сетевая ошибка или тело больше 80 МБ дают `error`

### Requirement: Проверка, что скачан нужный выпуск
Наблюдатель SHALL принимать файл, только если это нужный месяц: для `pdf` тело начинается с `%PDF`, и строка
`{Month} {yyyy}` есть в первых 1500 символах текста первых трёх страниц (для `html` — текста первых 400 000 байт без
тегов) или самый частый «Month yyyy» в этом тексте равен выпуску. Ссылка `latest_url` пробуется только для самого
свежего из `targets`, после ссылок `urls`.

#### Scenario: Ссылка «последний выпуск» отдала прошлый месяц
- **WHEN** для OPEC MOMR 2026-11 `latest_url` отдаёт PDF с обложкой «October 2026»
- **THEN** статус — `wrong_edition` с пояснением «на обложке не «November 2026» (найдено: 2026-10)»
- **AND** при прямой ссылке `momr-november-2026.pdf` с обложкой «November 2026» статус — `downloaded`

### Requirement: Сохранение выпуска и дата публикации
Принятый файл SHALL сохраняться атомарно (через `.part`) в каталог выпусков под именем
`{org}_{report}_{edition}.{pdf|html}` в нижнем регистре и записываться в его `catalog.yaml` с `source`
(`watch` | `upload`), `download`, `sha256`, `fetched` и датой публикации; запись того же выпуска заменяется, старые
выпуски не удаляются. Дата публикации — по порядку: график серии (`published_by: schedule`), метка «Published»
страницы IEA (`document`), дата скачивания (`fetched`).

#### Scenario: Дата из графика
- **WHEN** скачан OPEC MOMR 2026-11
- **THEN** `published` — `2026-11-11`, `published_by` — `schedule`, в журнале — запись `save` со статусом `downloaded` и `sha256`

#### Scenario: Дата из страницы IEA
- **WHEN** у страницы IEA OMR 2026-08 метка «Published» с `<time datetime="2026-08-13T10:00:00+02:00">`
- **THEN** `published` — `2026-08-13`, `published_by` — `document`, подпись — «опубликован 2026-08-13»

#### Scenario: Даты нет ни в графике, ни в документе
- **WHEN** сохранён EIA STEO 2026-11 (PDF, графика нет)
- **THEN** `published_by` — `fetched`, подпись выпуска — «скачан <сегодня> (дата публикации неизвестна)»

### Requirement: Проверка серий и расписание наблюдателя
`watch.check` SHALL за один проход выставить каждому выпуску из `targets` статус — `present`, `scheduled` или итог
скачивания — и при `REPORTS_WATCH_INGEST` (по умолчанию true) проиндексировать очередь; итог пишется в `state.json`,
шаги — в `journal.jsonl` каталога выпусков. Одновременно идёт одна проверка или индексация. Сервис
инструментов запускает проверку сам: через 120 с после старта (`REPORTS_FETCH_ON_START`, по умолчанию true) и затем
каждые `REPORTS_WATCH_HOURS` ч (по умолчанию 6).

#### Scenario: Выпуски уже в базе
- **WHEN** проверка идёт 2026-10-24, а файлы OPEC MOMR 2026-10 и 2026-09 на месте
- **THEN** оба выпуска получают `present` (в пояснении — имя файла), запросов к opec.org нет

#### Scenario: Выпуск ещё не вышел
- **WHEN** проверка идёт 2026-11-03, у IEA OMR `earliest_day: 11`, выпуска 2026-11 нет
- **THEN** его статус — `scheduled` с пояснением «выходит не раньше 2026-11-11»

#### Scenario: Параллельный запуск
- **WHEN** идёт плановая проверка и запускается `oilo reports --check`
- **THEN** вторая проверка возвращает `{"status": "busy", "note": "проверка или индексация уже идёт"}`

#### Scenario: Только проверка при старте
- **WHEN** `REPORTS_WATCH_HOURS=0`, а `REPORTS_FETCH_ON_START=true`
- **THEN** проходит одна проверка (`trigger: startup`) и больше по расписанию не запускается
- **AND** при `REPORTS_WATCH_HOURS=0` и `REPORTS_FETCH_ON_START=false` расписания нет, остаются `oilo reports --check` и `--upload`

### Requirement: Ручная загрузка выпуска
Система SHALL принимать выпуск файлом только командой `oilo reports --upload файл.pdf` (HTTP-эндпоинта загрузки
нет), под той же блокировкой, что и проверка: PDF до 80 МБ, серия — первая, все слова `detect` которой есть на первых
трёх страницах, выпуск — самый частый «Month yyyy», и он MUST соответствовать `20\d\d-(0[1-9]|1[0-2])`. Выпуск
сохраняется с `source: upload` и индексируется сразу, если нет `--no-index`.

#### Scenario: Серия и месяц по обложке
- **WHEN** загружен PDF с обложкой «OPEC Monthly Oil Market Report 12 August 2026»
- **THEN** выпуск — OPEC MOMR 2026-08 с `source: upload`, и `opec-momr-2026-08` в очереди индексации

#### Scenario: Файл не принят
- **WHEN** загружаются байты без `%PDF` в начале
- **THEN** загрузка отклоняется с ошибкой «это не PDF»
- **AND** если серия не узнана — «не удалось определить серию по обложке — укажите её явно»

#### Scenario: Идёт проверка
- **WHEN** загрузка начата во время проверки сайтов
- **THEN** она отклоняется с ошибкой «идёт проверка или индексация выпусков — повторите через минуту»

### Requirement: Очередь индексации и заморозка на время eval
Очередь SHALL содержать выпуски с `source` `watch` или `upload`, чей файл есть, а в отметках индекса
(`<каталог выпусков>/index_state.json`) их нет или там другой `sha256`. Индексация очереди MUST NOT менять индекс,
пока действует блокировка eval (`freeze.py`, файл `var/eval.lock`) или кодировщик сам строит базу: выпуски пишутся в
журнал как `queued` с причиной, а наблюдатель при `REPORTS_WATCH_INGEST` повторяет попытку раз в 600 с.

#### Scenario: Идёт замер eval
- **WHEN** `POST /api/eval_lock {"active": true}` поставил блокировку, а в очереди `opec-momr-2026-11`
- **THEN** выпуск остаётся в очереди с пояснением «идёт замер eval: данные обновятся после»
- **AND** блокировка, чей файл старше 3 ч, не действует

#### Scenario: Кодировщик строит базу сам
- **WHEN** `GET /ingest` кодировщика отвечает `{"active": true, "trigger": "auto"}`
- **THEN** результат — `queued` с причиной «кодировщик строит базу: новые выпуски он возьмёт сам после текущей загрузки»

#### Scenario: Чужая загрузка уже взяла выпуск
- **WHEN** кодировщик был занят другой загрузкой (до 5 попыток), а после её окончания очередь пуста
- **THEN** повторной векторизации нет, пояснение — «выпуски проиндексировала другая загрузка»

#### Scenario: Выпуск проиндексирован
- **WHEN** блокировок нет и загрузка выпуска прошла
- **THEN** в журнал пишется запись `index` со статусом `indexed` и пояснением «N фрагментов, разбор S с»

### Requirement: Разбор документов
Индексация SHALL разбирать PDF через Docling (без OCR, таблицы TableFormer в режиме `DOCLING_TABLE_MODE`, по
умолчанию `FAST`; без колонтитулов и картинок), а если Docling не установлен — постранично pypdf; HTML (IEA OMR) —
основной текст страницы до заголовка «Previous editions», «Newsletters», «Podcasts» или «Related». Разбор кэшируется
в `var/parsed/<doc_id>.json` и берётся из кэша, пока файл не новее кэша.

#### Scenario: Переиндексация без нового разбора
- **WHEN** `oilo ingest --recreate` после смены `indexing.chunk_tokens`
- **THEN** элементы берутся из `var/parsed`, заново считаются только фрагменты и векторы

#### Scenario: Потоки Docling
- **WHEN** `DOCLING_THREADS` пуст
- **THEN** Docling берёт `OMP_NUM_THREADS`, а без него — 4 потока CPU

### Requirement: Фрагменты отчётов
Фрагменты (`rag/chunks.py`) SHALL не пересекать страницу (у HTML — раздел) и иметь целевой размер
`indexing.chunk_tokens` (450) / 1.3 слова, но не меньше 80; фрагменты короче 8 слов отбрасываются. Таблица —
отдельный фрагмент без пробелов-заполнителей и точек, с подписью «Table N…» первой строкой. К тексту для
векторизации добавляется префикс с агентством, отчётом, выпуском, датой публикации, разделом и страницей.

#### Scenario: Подпись таблицы из заголовка или строки перед ней
- **WHEN** на странице 33 STEO таблица идёт в разделе «Table 3a. World Petroleum …»
- **THEN** фрагмент таблицы начинается с этой подписи, и его `section` — подпись
- **AND** при разделе «Sources:» подписью становится строка «Table 4b. …» перед таблицей на той же странице

#### Scenario: Большая таблица
- **WHEN** таблица OPEC «Table 1 - 1: OPEC Reference Basket, US$/b» из 120 строк больше двух целевых размеров
- **THEN** она режется на части, и каждая начинается с подписи и строки шапки `| Crude | Aug | Sep |`

#### Scenario: Префикс фрагмента
- **WHEN** фрагмент со страницы 6 EIA STEO 2026-10 (опубликован 2026-10-06)
- **THEN** префикс — «EIA STEO (Short-Term Energy Outlook), выпуск октябрь 2026, опубликован 2026-10-06; раздел: …; стр. 6.»

### Requirement: Индекс и сервис кодировщика
Индекс SHALL храниться в коллекции Qdrant `QDRANT_COLLECTION` (по умолчанию `reports`; без `QDRANT_URL` —
локально в `var/qdrant`) с векторами `dense` (cosine) и `sparse` BGE-M3 и индексами payload `org`, `report`,
`edition`, `doc_id`; перед повторной загрузкой выпуска его фрагменты удаляются, отметка (`chunks`, `at`, `sha256`)
пишется в `index_state.json`. Модели и разбор живут в кодировщике (`rag/encoder_service.py`, порт 8020): с
`ENCODER_URL` векторы запросов и загрузка идут через него.

#### Scenario: Здоровье кодировщика
- **WHEN** модели ещё грузятся или уже загружены
- **THEN** `GET /health` отвечает 200 со `status` `loading` или `ok`, списками `loaded` и `expected` (`emb`, и `rr` при `RERANKER=bge-…`)
- **AND** если загрузка сорвалась — 503 со `status: error` и `load_error`; повтор загрузки раз в минуту

#### Scenario: Кодировщик сам достраивает базу
- **WHEN** модели загружены и `AUTO_INGEST=true` (по умолчанию)
- **THEN** он индексирует выпуски с файлом, которых нет в отметках или чей `sha256` изменился, а при пустой коллекции — все
- **AND** `POST /ingest` во время идущей загрузки отвечает `started: false`

#### Scenario: Первый запуск, модели ещё качаются
- **WHEN** `/embed` не отвечает вовремя, а `/health` показывает `loaded` короче `expected`
- **THEN** клиент повторяет запрос (до 30 попыток), а не роняет загрузку

#### Scenario: Кодировщик занят при загруженных моделях
- **WHEN** запрос к `/embed` не отвечает вовремя, а модели загружены
- **THEN** клиент сразу падает с ошибкой «кодировщик … не ответил вовремя (долгий реранкинг на CPU?)»

### Requirement: Гибридный поиск с приоритетом последнего выпуска
`rag/retriever.retrieve` SHALL искать все запросы одной пачкой в Qdrant (в каждом dense и sparse по
`retrieval.prefetch` = 40 сливаются RRF, оценки фрагмента по запросам складываются) и упорядочивать кандидатов по
реранкеру, а при `RERANKER=none` (по умолчанию) — по RRF, нормированной на лучшую, плюс `latest_edition_bonus` = 0.15
последнему выпуску серии (и при отборе кандидатов). Кандидатов — `rerank_candidates` = 24, в итоге — `top_k`
(по умолчанию 6).

#### Scenario: Сумма RRF по запросам
- **WHEN** фрагмент «b» второй по обоим запросам, а «a» и «c» — первые по одному
- **THEN** порядок — `b`, `a`, `c`, и оба запроса ушли в Qdrant одним вызовом

#### Scenario: Выпуск назван или ждёт индекса
- **WHEN** задан `edition_filter: ["2026-09"]`
- **THEN** поиск идёт только по этому выпуску, надбавки нет ни у одного фрагмента
- **AND** выпуск из очереди индексации последним выпуском серии не считается

#### Scenario: Сравнение агентств
- **WHEN** фильтр `orgs: ["OPEC", "IEA"]`, лимит 6, и все лучшие оценки у OPEC
- **THEN** поиск идёт отдельно по каждому агентству, и в итоге не меньше 3 фрагментов IEA и не меньше 3 OPEC

#### Scenario: Метка фрагмента
- **WHEN** фрагмент со страницы 6 EIA STEO 2026-10
- **THEN** метка — «Отчёт EIA STEO, октябрь 2026, с. 6», а у фрагмента HTML — «…, раздел «…»»
