# price-forecast Specification

## Purpose
Расчётный модуль агента: дневные ряды цен EIA (Brent, WTI; спот газа Henry Hub — только рядом с котировкой), их
загрузка, обновление и дата данных; статистический
прогноз на 1–12 месяцев с интервалами по собственному бэктесту; сценарий шока предложения; история цен. Агент
вызывает его инструментами `forecast_price`, `supply_shock_scenario`, `price_history` (граф `graphs/calc.py`),
консоль — через API вкладки «Прогноз». Схемы аргументов MCP — спека `mcp-tools`.

## Requirements

### Requirement: Ряды цен EIA
Прогноз и история SHALL опираться на дневные ряды EIA `brent` (`RBRTEd.xls`) и `wti` (`RWTCd.xls`), $/барр.; ряд
`henry_hub` (`RNGWHHDd.xls`, $/MMBtu) MUST служить только спотом рядом с котировкой газа. Источник —
`https://www.eia.gov/dnav/{pet|ng}/hist_xls/{файл}` без ключа; лист `Data 1`, заголовок — третья строка, у повторной
даты — последнее значение. Ряда Urals нет: он строится из Brent.

#### Scenario: Снимок в репозитории
- **WHEN** есть только снимок `data/prices`
- **THEN** у `brent` дата данных `as_of` — 2026-10-14 и последняя цена 126.55, у `wti` — 2026-10-14 и 101.91
- **AND** ряд Brent начинается 1987-05-20, WTI — 1986-01-02
- **AND** у `henry_hub` снимок — по 2026-10-20, последняя цена 3.10; `forecast_price` и `price_history` его не принимают

#### Scenario: Неизвестный ряд
- **WHEN** вызывается `data.load("dubai")`
- **THEN** ошибка ValueError «неизвестный бенчмарк 'dubai'; есть: brent, wti, henry_hub (+ urals через Brent)»

### Requirement: Выбор файла и дата данных
`forecast/data.load` SHALL читать оба кандидата — `var/prices/<file>` (обновление) и `data/prices/<file>` (снимок в
git) — и брать ряд с более поздней последней датой (при равенстве — `var/prices`). `as_of` — дата последнего
дневного наблюдения, `last_price` — его значение. Месячный ряд — цена на конец месяца (`resample("ME").last()`):
текущий неполный месяц получает последнее дневное значение и дату конца месяца.

#### Scenario: Обновление свежее снимка
- **WHEN** `var/prices/RBRTEd.xls` кончается 2026-10-20, а снимок — 2026-10-14
- **THEN** `as_of` — 2026-10-20, `source_file` — файл из `var/prices`

#### Scenario: Неполный месяц
- **WHEN** последнее наблюдение Brent — 126.55 на 2026-10-14
- **THEN** последняя точка месячного ряда — 2026-10-31 со значением 126.55

#### Scenario: Файлов нет
- **WHEN** файла нет ни в `var/prices`, ни в `data/prices`
- **THEN** ошибка FileNotFoundError «нет файла цен RBRTEd.xls ни в var/prices, ни в data/prices»

### Requirement: Обновление цен
`forecast/data.refresh` SHALL скачивать файлы всех рядов через `net.outbound` (OUTBOUND_PROXY, CA_BUNDLE; таймаут 60 с, с
редиректами, `User-Agent: Mozilla/5.0 (oil-ouroboros; research)`) во временный файл и заменять `var/prices/<file>`,
только если он читается как таблица EIA. Ошибка одного ряда не прерывает обновление другого и не трогает прежние
данные: расчёты идут по последнему удачному файлу или снимку.

#### Scenario: Удачное обновление
- **WHEN** EIA отдаёт все три файла с данными по 2026-10-20
- **THEN** результат — `{"brent": "ok, последняя дата 2026-10-20", "wti": "ok, последняя дата 2026-10-20",
  "henry_hub": "ok, последняя дата 2026-10-20"}`

#### Scenario: EIA недоступна
- **WHEN** запрос к eia.gov падает или вместо таблицы приходит страница
- **THEN** у ряда результат «ошибка: …», файл в `var/prices` не меняется, `as_of` остаётся прежним

#### Scenario: Команды
- **WHEN** выполняется `oilo prices refresh`
- **THEN** обновление идёт сразу, без проверки блокировки eval, и печатается результат JSON
- **AND** `oilo prices show` печатает по каждому ряду имя, `as_of`, последнюю цену и файл

### Requirement: Расписание обновления цен
Сервис инструментов SHALL обновлять цены сам: через 30 с после старта, затем каждые `PRICES_REFRESH_HOURS` ч (по
умолчанию 6; 0 — расписания нет). Пока действует блокировка eval (`freeze.py`), плановое обновление пропускается с
причиной и повторяется через 600 с; после исключения следующая попытка — через `PRICES_REFRESH_HOURS`. Если дата
данных изменилась, прогнозы Brent и WTI на 3 мес. пересчитываются заранее (новая дата — новый ключ кэша бэктеста).

#### Scenario: Данные сдвинулись
- **WHEN** до обновления `as_of` всех рядов 2026-10-14, после — 2026-10-20
- **THEN** прогрев прогнозов вызывается один раз, а `refresh_status()["as_of"]["brent"]` — 2026-10-20

#### Scenario: Идёт замер eval
- **WHEN** действует блокировка eval
- **THEN** `refresh` не вызывается, `skipped` — «идёт замер eval: данные обновятся после»

#### Scenario: Состояние обновления
- **WHEN** запрашивается `GET /api/health` сервиса инструментов
- **THEN** поле `prices` содержит `as_of` по рядам, `last_refresh`, `next_refresh`, `result` и `skipped`

#### Scenario: У ряда ещё нет файла
- **WHEN** у одного ряда нет ни обновления, ни снимка
- **THEN** плановое обновление всё равно скачивает все ряды: дата этого ряда до обновления считается пустой

### Requirement: Модели и выбор метода
Прогноз SHALL строиться по месячному ряду в лог-ценах моделями statsforecast: `rw` (Naive), `drift`
(RandomWalkWithDrift), `ets` (AutoETS), `arima` (AutoARIMA, p и q ≤ 3, без сезонности), `theta` (AutoTheta) и
`ensemble` — среднее ets, arima и theta в лог-шкале. Горизонт ограничивается диапазоном 1..`forecast.max_horizon`
(12). Метод `auto` — метод с наименьшей RMSE лог-ошибки бэктеста на запрошенном горизонте, включая `rw`.

#### Scenario: Неверные аргументы
- **WHEN** запрошен метод `prophet`
- **THEN** ошибка ValueError «метод 'prophet' не поддержан; есть auto, rw, drift, ets, arima, theta, ensemble»
- **AND** для ряда `dubai` — «бенчмарк 'dubai' не поддержан; есть brent, wti, urals»

#### Scenario: Горизонт больше предела
- **WHEN** `service.forecast("brent", 24)`
- **THEN** `horizon_months` результата — 12

### Requirement: Бэктест и интервалы
Интервалы и скилл SHALL браться из rolling-origin бэктеста (расширяющееся окно, шаг 1 мес.) на
`forecast.backtest_windows` (60) окнах и горизонтах 1..`max_horizon`. Интервалы 50/80/95% — эмпирические квантили
ошибок выбранного метода на каждом горизонте в лог-шкале (split conformal с поправкой конечной выборки). Бэктест
кэшируется в `var/forecast_cache/backtest_<ряд>_<as_of>_<хэш>.json` по ряду, дате данных, горизонту и числу окон.

#### Scenario: Порядок границ
- **WHEN** считается прогноз Brent на 3 мес.
- **THEN** в каждой точке пути `lo95 ≤ lo80 ≤ lo50 ≤ median ≤ hi50 ≤ hi80 ≤ hi95`

#### Scenario: Таблица скилла и покрытие
- **WHEN** бэктест готов
- **THEN** по каждому методу и горизонту есть `rmse_log`, `rel_rmse_vs_rw`, `hit_rate` и `dm_p_vs_rw` (у `rw` — нет; DM с поправкой HLN, меньше 8 окон — NaN) и `n`
- **AND** покрытие считается честно: квантили — по ранним 2/3 окон (не меньше 5), проверка — по поздней трети

#### Scenario: Битый кэш
- **WHEN** файл кэша бэктеста не читается
- **THEN** бэктест пересчитывается и кэш перезаписывается

### Requirement: Результат прогноза и дата данных
Результат `forecast/service.forecast` SHALL явно нести дату данных: `as_of`, `last_price`, `last_month_end` и
`data_source` «{ряд}; наблюдения по {as_of}», а также путь `path` (дата конца месяца, `h`, `median`, `lo50…hi95`),
скилл, покрытие, лучший метод по горизонтам, медианы всех методов, детерминированную интерпретацию (не LLM) и
оговорки. Признака устаревания данных нет: о свежести говорят только эти поля. Результаты кэшируются в памяти по
(ряд, горизонт, метод, `as_of`), до 200 записей.

#### Scenario: Прогноз Brent на 3 месяца
- **WHEN** данные Brent по 2026-10-14
- **THEN** интерпретация начинается с «BRENT: последняя цена 126.55 $/барр. (на 2026-10-14).», `last_month_end` — 2026-10-31
- **AND** даты пути — 2026-11-30, 2026-12-31, 2027-01-31

#### Scenario: Оговорки
- **WHEN** горизонт 9 мес.
- **THEN** `caveats` — строки `forecast.caveats` каталога и «Горизонт больше 6 месяцев: подавайте результат как условный сценарий, а не как предсказание.»

### Requirement: Urals как оценка от Brent
Urals SHALL считаться от Brent с дисконтом `forecast.scenario.urals_discount` (low 15, base 25, high 31 $/барр.;
каталог требует low ≤ base ≤ high): история и медиана прогноза — Brent − base, нижние границы интервалов — с
дисконтом high, верхние — с low. Результат Urals помечается как оценка, а не котировки.

#### Scenario: История Urals
- **WHEN** запрошена дневная история Urals, Brent на 2026-10-14 — 126.55
- **THEN** точка 2026-10-14 — 101.55, а `source` — «Brent spot FOB (EIA RBRTE) минус ТЕКУЩИЙ базовый дисконт Urals: оценка, не котировки (дисконт в прошлом был другим)»

#### Scenario: Прогноз Urals
- **WHEN** запрошен прогноз Urals
- **THEN** `last_price` — последняя цена Brent − 25, `data_source` оканчивается на «; Urals = Brent − дисконт», `urals_discount` — с источниками
- **AND** в оговорках — «Urals = прогноз Brent минус базовый дисконт $25; интервалы учитывают дисконт 15–31 (сценарий); официального ряда Urals в открытом доступе нет.»

### Requirement: Сценарий шока предложения
`forecast/scenario.supply_shock` SHALL считать импульс по формуле s = −Δ·c·(1−o)/Q, ln(P/P0) = s / (ε_S + |ε_D|)
для каждого пресета эластичностей каталога (`kilian_low` 0.02/−0.13, `cci` 0.13/−0.13, `bh` 0.20/−0.35) и канал
запасов по `inventory_rule` ($10–20/барр. на 1 млн б/с, Goldman Sachs), где Q = `world_supply_mbd` (102.3), c —
исполнение, o — компенсация (доли 0..1). P0 в `service.shock` — медиана прогноза `auto` на тот же горизонт.

#### Scenario: Сокращение на 2 млн б/с
- **WHEN** Δ = −2, P0 = 100, исполнение 1, компенсации нет
- **THEN** доля шока 0.01955; импульс `kilian_low` +13.92% (113.92), `cci` +7.81%, `bh` +3.62%; канал запасов (20.0, 40.0)
- **AND** объяснение начинается с «С рынка уходит 2.00 млн б/с (1.96% мирового предложения 102.3 млн б/с; исполнение 100%, компенсация 0%).»

#### Scenario: Шок вне калибровки
- **WHEN** |s| больше `applicability_share` (0.05), например Δ = −10
- **THEN** `within_calibration` — false, `inventory_channel_usd` — null, в объяснении — «вне диапазона» и «только порядок величины»

#### Scenario: Компенсация не учитывается дважды
- **WHEN** Δ = −2 и компенсация 0.5
- **THEN** канал запасов — (20.0, 20.0): с компенсацией берётся только оценка «без ответа OPEC+»
- **AND** при исполнении 1.5 — ошибка «compliance и offset — доли от 0 до 1»

### Requirement: История цен
`forecast/service.history(benchmark, start, freq)` SHALL отдавать месячные (`M`, цена на конец месяца) или дневные
(`D`) значения ряда с даты `start`, округлённые до центов, вместе с `as_of` ряда, `source` и статистикой `last`,
`min`, `max`, `mean` по тем же точкам.

#### Scenario: Месячная история Brent
- **WHEN** запрошена история Brent с 2026-08-01, `freq=M`
- **THEN** точки — 2026-08-31: 89.75, 2026-09-30: 115.91, 2026-10-31: 126.55, а `as_of` — 2026-10-14
- **AND** статистика — `last` 126.55, `min` 89.75, `max` 126.55, `mean` 110.74

### Requirement: Инструменты расчёта для агента
Граф `graphs/calc.py` (узлы `compute` → `pack`, без LLM) SHALL отдавать агенту три строки: «[F#] {метка} · пакет
P# · trace {id}», JSON расчёта и «Цитируй [F#] в каждом предложении с цифрами этого расчёта; интервалы и оговорки
передай пользователю.» Расчёт кладётся в журнал доказательств как F# уровня 0: те же инструмент, аргументы, дата
данных и текст — тот же F#. Ошибка расчёта уходит агенту как isError «{класс}: {текст} (trace {id})».

#### Scenario: forecast_price
- **WHEN** агент вызывает `forecast_price` для Brent на 3 мес. при данных по 2026-10-14
- **THEN** метка — «Расчёт: прогноз Brent на 3 мес., данные EIA по 2026-10-14»
- **AND** в JSON скилл только выбранного метода и `rw` на горизонтах 1 и 3

#### Scenario: price_history
- **WHEN** агент вызывает `price_history` без аргументов
- **THEN** берутся месячные точки Brent с 2025-01-01; больше 40 точек — каждая `len // 36`-я и последняя
- **AND** метка — «Расчёт: история цен Brent (EIA) с 2025-01-01» без даты данных: она только в поле `as_of` JSON

#### Scenario: supply_shock_scenario
- **WHEN** агент вызывает `supply_shock_scenario` с `delta_mbd=-2`
- **THEN** метка — «Расчёт: сценарий -2 млн б/с, Brent; запасы — оценка Goldman Sachs», в JSON — `baseline_median`, `baseline_interval80`, `as_of` и `scenario`

### Requirement: API вкладки «Прогноз»
Сервис инструментов SHALL отдавать `GET /api/forecast` (`benchmark`=brent, `horizon`=3, `method`=auto; полный
результат со всей таблицей скилла), `GET /api/forecast/history` (`start`=2024-01-01, `freq`=M; без прореживания) и
`GET /api/forecast/scenario` (`delta_mbd` обязателен; `benchmark`, `horizon`, `compliance`=1, `offset`=0). Консоль
проксирует их с токеном `TOOLS_API_TOKEN`; они открыты без входа, вкладка есть в обоих режимах. При старте tools прогноз Brent и
WTI на 3 мес. считается в фоне.

#### Scenario: Запросы вкладки
- **WHEN** открыта вкладка «Прогноз» (`ui/forecast.js`)
- **THEN** она запрашивает прогноз с выбранными рядом, горизонтом 1–12 и методом и историю с `start=2018-01-01`, `freq=M`
- **AND** сценарий — `GET /api/forecast/scenario` через 450 мс после изменения ползунков

#### Scenario: Ошибка расчёта
- **WHEN** расчёт падает (например, нет файлов цен)
- **THEN** API отвечает HTTP 500 (своего обработчика ошибок нет), вкладка показывает блок ошибки
