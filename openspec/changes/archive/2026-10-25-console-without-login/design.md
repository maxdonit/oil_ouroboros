# Design

## Context

Мотивация — proposal.md, «Why». Сейчас вход и роли — middleware `auth` в `console/app.py:83-113`:
- Basic по `UI_USERS`, `_parse_users`, `_login`;
- открытый режим `UI_OPEN` при `OILO_BIND=127.0.0.1`;
- `allowed(role, method, path)` и `ROLE_TABS`.

От этого зависят:
- `/api/me` — UI берёт оттуда вкладки (`ui/main.js:154-158`);
- урезанный `/api/health` без входа;
- привязка разговора к логину (`_conv_prefix`, `_own`).

`init_env.py:41-43` генерирует `UI_USERS`. Compose передаёт консоли `UI_USERS` и `OILO_BIND`.

## Goals / Non-Goals

**Goals:** после `docker compose up` консоль открывается без единого вопроса; простой режим по умолчанию, режим
администратора — одной кнопкой; из кода, конфигурации и документов уходит всё про логины консоли.

**Non-Goals:** пароль UI Ouroboros и межсервисные токены (proposal.md, Non-goals).

## Decisions

1. **Как выбрать режим.** Варианты:
   - (a) экран выбора режима при каждом входе;
   - (b) сразу простой режим и кнопка «Режим администратора» в шапке;
   - (c) роли на сервере, переключаемые cookie.

   **Выбран (b).** На шаг меньше, чем (a), и пользователь сам назвал этот вариант. (c) — лишняя сложность: защиты
   всё равно нет, а сервер должен был бы знать режим.
2. **Режим живёт только в интерфейсе.**
   - Набор вкладок простого режима (`chat`, `forecast`) — константа в `ui/main.js`.
   - Выбор хранится в `localStorage` (`oil.mode`: `simple` | `admin`, по умолчанию `simple`) через существующий
     `store` из `ui/util.js`.
   - `session` в `util.js` заменяется на `mode`; `canOpen(tab)` смотрит на текущий режим.
   - `/api/me`, `ROLES`, `ROLE_TABS`, `allowed`, `_parse_users`, `_login`, `_local` удаляются. Middleware остаётся
     только для `Cache-Control`.
3. **Кнопка режима** стоит в шапке вместо `#whoami` и называет действие: «Режим администратора» или «Простой
   режим». Переключение перестраивает навигацию. Если текущая вкладка в простом режиме недоступна — переход в «Чат».
4. **Ссылка на вкладку администратора** в простом режиме (`#/turns/<id>` из ссылки, `#/quality/<id>`) включает режим
   администратора. Ссылка не должна молча вести в «Чат», а преград всё равно нет.
5. **Разговоры.**
   - id нового разговора — `c-<10 hex>`; `_own` и `_conv_prefix` удаляются.
   - Прежние id `c-<12 hex>-<10 hex>` — просто строки: журнал ходов ищет по `conversation_id` как есть.
6. **Параметры.**
   - Из `Settings` удаляются `ui_users`, `ui_open`, `oilo_bind`. Консоль `OILO_BIND` больше не читает, compose — не
     передаёт.
   - `OILO_BIND` остаётся переменной compose для `ports` (консоль и UI Ouroboros).
   - Спец-случай `name == "ui_users"` в `describe_settings` (`config.py:171`) уходит.
   - Новых параметров нет.
   - Отпечаток агента от `Settings` консоли не зависит (`console/fingerprint.py` читает засев и каталог), поэтому
     версия агента прежняя.
7. **Чтобы не вернулось.** В `LEGACY` (`tests/test_consistency.py`) добавляются `UI_USERS` и `UI_OPEN`; `/api/me` упомянут в самой спеке («эндпоинта нет»), его отсутствие проверяет тест маршрутов.
   Тест-проверка `OILO_BIND` в окружении консоли (`test_compose_gives_console_its_publish_address`) удаляется
   вместе с требованием.

## Risks / Trade-offs

- [Консоль, опубликованная в сеть (`OILO_BIND=0.0.0.0` или адрес стенда), открыта всем в этой сети, включая запуск
  eval и траты LLM] → это решение владельца. Лимит денег шлюза (`GATEWAY_BUDGET_USD`) остаётся жёстким потолком.
  Документы прямо говорят: «консоль без входа; публикация в сеть открывает её всем в сети».
- [Старые закладки и токены браузера с Basic-авторизацией] → сервер заголовок `Authorization` игнорирует, ничего не
  ломается.
- [Режим запоминается на браузер, а не на человека] → это ожидаемо: режим — удобство, а не право.

## Migration Plan

`python scripts/deploy.py up`. На стенде из `.env` удаляется строка `UI_USERS`: compose её больше не передаёт, строка
только сбивает с толку. Откат — `git revert`, выкладка и возврат строки `UI_USERS` из резервной копии `.env`.
