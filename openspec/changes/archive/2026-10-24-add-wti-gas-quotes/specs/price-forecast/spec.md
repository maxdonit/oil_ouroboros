# Spec Delta

## MODIFIED Requirements

### Requirement: Ряды цен EIA
Прогноз и история SHALL опираться на дневные ряды EIA `brent` (`RBRTEd.xls`) и `wti` (`RWTCd.xls`), $/барр.; ряд
`henry_hub` (`RNGWHHDd.xls`, $/MMBtu) MUST служить только спотом рядом с котировкой газа. Источник —
`https://www.eia.gov/dnav/{pet|ng}/hist_xls/{файл}` без ключа; лист `Data 1`, заголовок — третья строка, у повторной
даты — последнее значение. Ряда Urals нет: он строится из Brent.

#### Scenario: Снимок в репозитории
- **WHEN** есть только снимок `data/prices`
- **THEN** у `brent` дата данных `as_of` — 2026-10-14 и последняя цена 126.55, у `wti` — 2026-10-14 и 101.91
- **AND** ряд Brent начинается 1987-05-20, WTI — 1986-01-02
- **AND** у `henry_hub` снимок — по 2026-10-20, последняя цена 3.10; `forecast_price` и `price_history` его не принимают

#### Scenario: Неизвестный ряд
- **WHEN** вызывается `data.load("dubai")`
- **THEN** ошибка ValueError «неизвестный бенчмарк 'dubai'; есть: brent, wti, henry_hub (+ urals через Brent)»

### Requirement: Обновление цен
`forecast/data.refresh` SHALL скачивать файлы всех рядов через `net.outbound` (OUTBOUND_PROXY, CA_BUNDLE; таймаут 60 с, с
редиректами, `User-Agent: Mozilla/5.0 (oil-ouroboros; research)`) во временный файл и заменять `var/prices/<file>`,
только если он читается как таблица EIA. Ошибка одного ряда не прерывает обновление другого и не трогает прежние
данные: расчёты идут по последнему удачному файлу или снимку.

#### Scenario: Удачное обновление
- **WHEN** EIA отдаёт все три файла с данными по 2026-10-20
- **THEN** результат — `{"brent": "ok, последняя дата 2026-10-20", "wti": "ok, последняя дата 2026-10-20",
  "henry_hub": "ok, последняя дата 2026-10-20"}`

#### Scenario: EIA недоступна
- **WHEN** запрос к eia.gov падает или вместо таблицы приходит страница
- **THEN** у ряда результат «ошибка: …», файл в `var/prices` не меняется, `as_of` остаётся прежним

#### Scenario: Команды
- **WHEN** выполняется `oilo prices refresh`
- **THEN** обновление идёт сразу, без проверки блокировки eval, и печатается результат JSON
- **AND** `oilo prices show` печатает по каждому ряду имя, `as_of`, последнюю цену и файл

### Requirement: Расписание обновления цен
Сервис инструментов SHALL обновлять цены сам: через 30 с после старта, затем каждые `PRICES_REFRESH_HOURS` ч (по
умолчанию 6; 0 — расписания нет). Пока действует блокировка eval (`freeze.py`), плановое обновление пропускается с
причиной и повторяется через 600 с; после исключения следующая попытка — через `PRICES_REFRESH_HOURS`. Если дата
данных изменилась, прогнозы Brent и WTI на 3 мес. пересчитываются заранее (новая дата — новый ключ кэша бэктеста).

#### Scenario: Данные сдвинулись
- **WHEN** до обновления `as_of` всех рядов 2026-10-14, после — 2026-10-20
- **THEN** прогрев прогнозов вызывается один раз, а `refresh_status()["as_of"]["brent"]` — 2026-10-20

#### Scenario: Идёт замер eval
- **WHEN** действует блокировка eval
- **THEN** `refresh` не вызывается, `skipped` — «идёт замер eval: данные обновятся после»

#### Scenario: Состояние обновления
- **WHEN** запрашивается `GET /api/health` сервиса инструментов
- **THEN** поле `prices` содержит `as_of` по рядам, `last_refresh`, `next_refresh`, `result` и `skipped`

#### Scenario: У ряда ещё нет файла
- **WHEN** у одного ряда нет ни обновления, ни снимка
- **THEN** плановое обновление всё равно скачивает все ряды: дата этого ряда до обновления считается пустой
