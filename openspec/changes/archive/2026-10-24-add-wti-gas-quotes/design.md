# Design

## Context

Мотивация — proposal.md. Котировка Brent уже работает (спека `price-quote`, `forecast/quotes.py`): ISS Мосбиржи,
выбор контракта по `forecast.quote.roll_days`, цена `LAST` → `SETTLEPRICE` → `PREVSETTLEPRICE`, время `SYSTIME`, кэш и
`var/quotes/brent.json`, заморозка eval, отказ `stale` / `unavailable`, спот EIA рядом. Сейчас актив `BR` и ряд спота
`brent` зашиты в код. Ответ ISS по `assets=…` для WTI, NG и TTF — того же вида (проверено со стенда 24.10.2026), у
всех трёх контрактов расчётное исполнение по фьючерсам NYMEX и ICE и торги в выходные (`WEEKENDSESSION=1`).

Единицы из описания контрактов ISS: BR и WTI — «В USD за 1 баррель», NG — «В USD за 1 MMBtu», TTF — «В EUR за 1
(один) мегаватт» (час). Спот EIA: Brent и WTI — уже скачиваемые `RBRTE` и `RWTC` (раздел `dnav/pet`), Henry Hub —
`RNGWHHD` (раздел `dnav/ng`, тот же формат xls, по 20.10 — 3.10), у TTF открытого дневного ряда нет.

## Goals / Non-Goals

**Goals:**
- текущая цена WTI, газа Henry Hub и TTF за один вызов, с единицей, контрактом и временем — как у Brent;
- новый сорт Мосбиржи — правкой каталога, без кода;
- поведение Brent не меняется: `price_quote()` без аргумента — прежний результат и прежняя метка.

**Non-Goals:**
- отдельные правила перехода на контракт для каждого сорта: общий `roll_days` подходит всем четырём (контракты
  истекают вместе с фронтом NYMEX / ICE); отдельное значение — когда понадобится;
- котировки в рублях и пересчёт валют.

## Decisions

**1. Один инструмент с аргументом `benchmark`, а не инструмент на сорт.** Модель выбирает «текущая цена» → `price_quote`,
а сорт — из вопроса, как в `forecast_price(benchmark)`. Девятый инструмент остаётся девятым: схема растёт на одно
поле-перечисление, а не на три инструмента (~150 токенов каждый в каждом ходе). Значение по умолчанию `brent`
сохраняет прежние вызовы, регламент и утреннюю сводку.

**2. Сорта — в каталоге `forecast.quote.instruments`.** Для каждого: `asset` (код ISS), `title` и `title_en` (для меток),
`unit` и `unit_en`, `eia` (ключ ряда спота или пусто). Схема каталога проверяет поля; перечисление в схеме
инструмента MCP строится из каталога при старте. Альтернатива — словарь в коде — проще, но каждый новый сорт стал бы
правкой кода и тестов вместо строки каталога. Каталог входит в версию агента, так что смена состава сортов видна в
«Мониторинге».

**3. Спот Henry Hub — третий ряд в `forecast/data.SERIES` с разделом EIA (`pet` / `ng`).** Тот же загрузчик, плановое
обновление, снимок в `data/prices` и строка во вкладке «Источники». Прогноз и история проверяют сорт по своему списку
(`brent`, `wti`, `urals`), поэтому газ туда не попадает. Альтернатива — отдельный загрузчик только для спота — дублирует
код обновления, заморозки и показа свежести.

**4. Состояние по сорту.** Кэш в памяти — словарь по сорту; файл — `var/quotes/<сорт>.json`; последняя ошибка — по сорту.
Блокировка и время кэша общие. Один запрос ISS на сорт (`assets=<код>`): общий запрос на все сорта сэкономил бы
вызовы, но связал бы отказ одного сорта с остальными и усложнил кэш.

**5. Метки — с названием сорта, у TTF без хвоста о споте.** «Котировка: {title}, фьючерс {контракт} (Мосбиржа, задержка
15 мин), {время}; спот EIA на {дата}»; у Brent `title` — «Brent», поэтому его метка прежняя. Английский шаблон `LABEL_EN`
переводит общий вид с `title_en`. Единица — в JSON (`unit`) и в тексте ответа агента, не в метке: метка Brent не
меняется.

**6. Раздел `quote` в `/api/sources` — список `instruments`.** Плитка «Котировка Brent» остаётся (главный сорт), под
таблицей цен EIA — таблица котировок всех сортов со статусом, контрактом, ценой с единицей и временем.

## Risks / Trade-offs

- [Единицы $/MMBtu и €/МВт·ч незнакомы проверке цифр: `verify_answer` может не подтвердить «2,628 $/MMBtu»] → тест с
  `verify_answer` по котировкам газа на записанном ответе ISS; если проверка единицу не узнаёт — число подтверждается
  как безразмерное (так же, как сейчас цены без единицы), правка распознавания единиц — отдельный change.
- [NG-10.26 за 4 дня до экспирации — тонкий рынок, а фронт NYMEX ещё ноябрь] → `roll_days` 3 переводит на NG-11.26 25.10,
  как и фронт NYMEX (экспирация ноябрьского — 28.10); значение одно на все сорта и меняется в каталоге.
- [TTF в евро: пользователь может ждать доллары] → единица в JSON и требование регламента называть её; пересчёт — не
  входит.
- [Модель зовёт `price_quote` без `benchmark` на вопрос о газе] → описание аргумента и регламент перечисляют сорта;
  кейсы eval с `tool_args` ловят неверный сорт.
- [Торги в выходные (`WEEKENDSESSION=1`)] → время — `SYSTIME`, правило плитки «старше предыдущего рабочего дня» не даёт
  ложной тревоги, если в выходные котировка обновилась.

## Migration Plan

1. Выкладка `python scripts/deploy.py up`; `deploy.py restart ouroboros` — агент перечитывает схему инструментов MCP.
   Засев обновит регламент и утреннюю сводку, если владелец их не менял.
2. Проверка: `oilo ask` по WTI, Henry Hub и TTF; вкладка «Источники»; выборочный eval (Q01, Q03–Q05) с согласия
   владельца.
3. Откат: `git revert` и повторная выкладка; файлы `var/quotes/*.json` новых сортов можно оставить.
