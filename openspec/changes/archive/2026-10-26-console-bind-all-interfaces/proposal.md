## Why

Шаблон `.env.example` публикует консоль и UI Ouroboros только на `127.0.0.1`: после установки на сервер консоль не
видна ни с другой машины в сети, ни через проброс порта роутера, и первым делом приходится править `OILO_BIND`. Решение
владельца — после установки в консоль должно быть легко попасть, поэтому по умолчанию порты слушают все адреса хоста.

## What Changes

- `.env.example`: `OILO_BIND=0.0.0.0` вместо `127.0.0.1`; комментарий — что это значит (консоль без пароля и UI
  Ouroboros по паролю видны в сети хоста) и как вернуть только эту машину (`127.0.0.1`).
- Запасное значение в `docker-compose.yml` (`${OILO_BIND:-127.0.0.1}`, когда `.env` нет) не меняется.
- Документы под новое значение: `INSTALL.md`, `docs/guide/parameters.md` (строка `OILO_BIND`),
  `docs/guide/operations.md` (раздел «Безопасность»), `docs/guide/owner.md` (риски пароля UI в сети).

## Capabilities

### New Capabilities

— нет.

### Modified Capabilities

- `deployment` — шаблон `.env` публикует консоль на всех адресах хоста (новый сценарий в требовании о сетях и
  портах).
- `owner-channel` — пароль по умолчанию UI Ouroboros проверяется на адресе из шаблона (`0.0.0.0:38630`).

## Non-goals

- Отдельный адрес публикации для консоли и UI Ouroboros: `OILO_BIND` остаётся общим.
- HTTPS, пароль консоли, ограничение доступа: консоль остаётся без входа.
- Значение по умолчанию в `docker-compose.yml` без `.env`.

## Impact

- Файлы: `.env.example`, `INSTALL.md`, `docs/guide/parameters.md`, `docs/guide/operations.md`, `docs/guide/owner.md`.
- Существующие `.env` не меняются: `scripts/init_env.py` создаёт `.env` из шаблона только при первом запуске.
- Версия агента не меняется: каталог, регламент и память агента не затронуты.
