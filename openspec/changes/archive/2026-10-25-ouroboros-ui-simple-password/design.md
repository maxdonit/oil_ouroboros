# Design

## Context

Мотивация — proposal.md, «Why». Как сейчас:
- `scripts/init_env.py:22-30` (`GENERATED`) заполняет пустой `OUROBOROS_PASSWORD` случайными 48 hex;
- засев (`bootstrap.render_settings`) требует непустое значение и кладёт его в `OUROBOROS_NETWORK_PASSWORD`;
- консоль (`agent.Ouroboros`, `console/fingerprint.py`) и расписания (`schedules.Api`) шлют его заголовком
  `X-Ouroboros-Password`.

Ouroboros 7.7.0 проверяет пароль для всех запросов не с loopback (`server_auth.NetworkAuthGate`): и для UI владельца
через `ouroboros-ui`, и для API из соседних контейнеров. Длину и сложность пароля он не ограничивает.

## Goals / Non-Goals

**Goals:** пароль UI Ouroboros известен сразу после установки — из README и из вывода `init_env.py`; ни строчки
кода в обход механизма Ouroboros; существующие установки не ломаются.

**Non-Goals:** работа Ouroboros без пароля; смена межсервисных токенов.

## Decisions

1. **Каким сделать пароль.** Варианты:
   - (a) Значение по умолчанию `ouroboros` в `.env.example`, README его называет, `init_env.py` его печатает.
   - (b) Оставить случайный пароль, но печатать его в конце `init_env.py`.
   - (c) Без пароля — с `OUROBOROS_TRUST_NONLOCAL_BIND_WITHOUT_PASSWORD=1` и необязательной переменной засева.

   **Выбран (a).** Пароль известен до установки и не теряется: он в README, его не надо выискивать ни в выводе
   скрипта, ни в `.env`. (b) снова отправляет в `.env`, если вывод потерян. (c) владелец отклонил: это обход проверки
   Ouroboros и правки засева.
2. **`init_env.py`.** `OUROBOROS_PASSWORD` убирается из `GENERATED`: значение приходит из шаблона.
   - Существующий `.env` с непустым паролем `--fill` не трогает, как и раньше.
   - Если пароль стёрт вручную, засев останавливается с прежней понятной ошибкой «не заданы переменные окружения …
     OUROBOROS_PASSWORD (.env)». Подставлять случайный пароль молча — снова прятать его.
   - В конце скрипт печатает адрес UI Ouroboros и пароль из получившегося `.env`.
3. **Ничего больше не меняется.** Засев, клиенты консоли и расписаний, compose и `x-no-secrets` остаются как есть.
   Пароль — по-прежнему секрет засева: в `settings_public` и в отпечаток версии агента он не попадает.

## Risks / Trade-offs

- [Пароль по умолчанию известен всем, кто читал README; на адресе в сети (`OILO_BIND`) UI с кодом и shell агента
  доступен любому в этой сети, кто его знает] → решение владельца. Смена — одна строка `.env`, это написано в
  README и `owner.md`.
- [Смена пароля на работающей системе: засев, Ouroboros, консоль и расписания должны получить его вместе, иначе
  консоль получит 401 от Ouroboros] → в `operations.md` уже есть порядок: `docker compose up -d` и
  `--force-recreate bootstrap ouroboros`. На стенде делается так же.

## Migration Plan

Новые установки получают пароль `ouroboros` из шаблона. На стенде:
- копия `.env`;
- `OUROBOROS_PASSWORD=ouroboros` в локальном и серверном `.env`;
- `python scripts/deploy.py up` — пересоздаёт `console` и `schedules` с новым паролем;
- пересоздание засева и Ouroboros (`docker compose up -d --force-recreate bootstrap ouroboros`).

Проверка: консоль видит Ouroboros (здоровье, живой ход), UI на 38630 без пароля отвечает страницей входа (401).
Пароль в браузер не вводится. Откат — прежнее значение из копии `.env` и то же пересоздание.
