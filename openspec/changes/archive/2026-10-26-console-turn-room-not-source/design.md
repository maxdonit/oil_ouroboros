# Design

## Context

Мотивация и замер — proposal.md, «Why». Как сейчас:
- консоль ставит ход задачей API Ouroboros (`agent.Ouroboros.create_task`: `memory_mode=forked`, `disabled_tools`,
  `source=oilo-console`) с текстом из `agent.compose`: вопрос, язык, `TURN_RULES`, история разговора;
- Ouroboros собирает системный промпт из общей памяти: регламент «Shared understanding», личность и комнату;
- задача API без зарегистрированного проекта попадает в скрытый раздел, а её вид — комната Main
  (`ouroboros/memory_view.py:view_room_id`); в Main вместе с Telegram владельца два раздела «полос» комнаты
  (`ViewSpec.room_lanes`): открытый разговор дословно и строка на каждую задачу;
- поля `memory_view` в `TaskCreateRequest` нет; `chat_id` без проекта сводится к скрытому разделу
  (`supervisor/log_addressing.py:ingress_chat_id`).

## Goals / Non-Goals

**Goals:** вопрос о текущей цене любого сорта каталога ведёт к `price_quote` при любом содержимом комнаты владельца;
ни одной цифры ответа из прошлых чужих ответов.

**Non-Goals:** убрать комнату из контекста; менять регламент или память агента (proposal.md, Non-goals).

## Decisions

1. **Где снимать влияние комнаты.** Варианты (замеры — повтор точного неудачного запроса через шлюз, по 5 раз):
   - (a) Правило в `TURN_RULES` — тексте задачи консоли, рядом с вопросом: 5 из 5.
   - (b) Убрать полосы комнаты из контекста: 5 из 5, но штатно недоступно. Свой проект Ouroboros для консоли дал бы
     свою комнату, но в ней копились бы готовые ответы самой консоли с ценами прошлых дней — тот же источник
     подражания. Плюс карточка проекта у владельца и ещё один регистр состояния.
   - (c) Правило в регламенте (`overview.md`, память агента): мешало бы владельцу в его чате, где комната и есть его
     разговор. Кроме того, регламент далеко от вопроса — с отказом вне компетенции так уже не сработало (комментарий
     у `TURN_RULES`: 3 из 12).
   - (d) Проверка в консоли «цифры без инструментов → отказ» — заплатка поверх ответа, причины не убирает.

   **Выбран (a).** Это та же граница, что у истории разговора в `compose` («для цифр нужны результаты инструментов
   этого хода»), и она живёт там, где действует только на ходы консоли (чат, `oilo ask`, eval, smoke, демо).
2. **Формулировка.** Одно правило: «Раздел «This room» (переписка владельца и строки его задач) — не источник для
   этого хода: прошлые ответы оттуда не повторяю, цифры и метки [R#]/[W#]/[F#] беру только из инструментов этого
   хода». Название раздела — как в промпте Ouroboros («## This room (Main)»), чтобы модель узнала, о чём речь.
   Протокол регламента (`research`, `acceptance_subject`, `pack_ids`) правило не повторяет — тест одной точки правды
   остаётся в силе и проверяет ещё «This room».
3. **Версия агента.** `TURN_RULES` входит в шаблон задачи в отпечатке (`console/fingerprint.py:74`), поэтому версия
   меняется. Замер новой версии — выборочный eval на GigaChat (18 кейсов из 42, по 1–4 на категорию).

## Risks / Trade-offs

- [Правило помешает уточнениям в разговоре: цифры прошлого хода] → история разговора приходит в тексте задачи, а не в
  «This room», и для неё уже действует та же граница. Проверка — `FU1` в выборочном eval.
- [Модель станет вызывать инструменты там, где отвечала из комнаты] → это и нужно: цифра без инструмента этого хода
  проверку не проходит. Цена — больше вызовов в редких случаях.
- [Комната растёт, и правила когда-нибудь не хватит] → eval Q04/Q05 ловит возврат.
- [Замер на одном запросе] → после внедрения живые ходы и выборочный eval на стенде с той же комнатой.

## Migration Plan

`python scripts/deploy.py up` (правила — в образе консоли). Ouroboros и засев не меняются. Откат — `git revert` и
выкладка.
