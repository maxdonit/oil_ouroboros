# Proposal

## Why

25.10 вопросы о цене газа Henry Hub в чате консоли в 4 случаях из 5 прошли без инструментов. Агент либо отказывал
(«это вне моей компетенции»), либо писал цену по памяти модели — 2,99 $/MMBtu со ссылкой `[F1]`, скопированной из
чужого ответа (0 из 2 цифр подтверждены). Накануне те же вопросы через `oilo ask` и eval (Q04) шли через
`price_quote`. Регламент и схема инструмента верны: газ в компетенции, `price_quote(henry_hub)` описан.

Причина — переписка владельца в контексте задачи консоли. Ouroboros собирает контекст задачи API без проекта по
комнате Main (`memory_view.view_room_id`), а в ней Telegram-разговор владельца:
- «Open conversation» — 11,4 тыс. символов готовых ответов о нефти с метками;
- «Task facts of this conversation» — 17,5 тыс. символов.

За сутки в комнату добавились новости по нефти и утренняя сводка, и GigaChat-3-Ultra стал подражать этим ответам
вместо вызова инструмента. Доказано повтором точного неудачного запроса через шлюз, по 5 раз на вариант:

| Вариант запроса | Вызов `price_quote` |
|---|---|
| как есть | 0 из 5 (склеенный промпт — 1 из 5) |
| без двух разделов комнаты (−29 тыс. символов) | 5 из 5 |
| как есть + одно правило хода (ниже) | 5 из 5 |

Вопрос о Brent в том же контексте проходил: газ к контексту «только нефть» чувствительнее.

## What Changes

- В правила хода консоли (`agent.TURN_RULES`) добавляется одно правило: «Раздел «This room» (переписка владельца и
  строки его задач) — не источник для этого хода: прошлые ответы оттуда не повторяю, цифры и метки [R#]/[W#]/[F#]
  беру только из инструментов этого хода». Это та же граница, что уже стоит у истории разговора («для цифр нужны
  результаты инструментов этого хода»), но для комнаты Ouroboros. Комментарий у правила называет замер.
- Правила хода входят в отпечаток, поэтому версия агента меняется. Сравнение — на «Качестве» по версиям.
- Проверка на стенде: живые вопросы о Henry Hub и TTF; выборочный eval на профиле по умолчанию (GigaChat) — 18
  кейсов из 42, по 1–4 на категорию, около 3 млн токенов (согласие владельца получено). Итоги — в `docs/report.md`
  вместо замера на 10 кейсах.

Не входит (Non-goals):
- Убрать комнату Main из контекста задач консоли. Штатного рычага нет: в API задач Ouroboros нет `memory_view`, а
  `chat_id` без проекта не принимается. Отдельный проект Ouroboros для консоли даёт свою комнату, но в ней копились бы
  готовые ответы самой консоли — тот же источник подражания, да ещё с устаревшими ценами (design.md, решение 1).
- Документы об устройстве (DESIGN, how_it_works) и новые строки плана: здесь только правило хода и замер.
- Регламент и память агента: регламент верен, а правило нужно только задачам консоли. Владелец в своём чате
  комнатой пользуется по праву.
- Проверка «цифры без инструментов → отказ» в консоли — это заплатка поверх модели. Финальная перепроверка и так
  помечает такие цифры как неподтверждённые.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `agent-turn`: в правилах хода консоли — раздел «This room» не источник; цифры и метки — только из инструментов этого
  хода.

## Impact

- Код: `src/oil_ouroboros/agent.py` (`TURN_RULES` и комментарий у него).
- Тесты: `tests/test_turns.py` (правило есть, протокол регламента в правилах по-прежнему не повторяется).
- Документы: `docs/report.md` и строка о качестве GigaChat в `docs/guide/parameters.md` (итоги замера).
- Версия агента меняется (шаблон задачи в отпечатке). Каталог и память агента не меняются.
- GigaChat: выборочный eval около 3 млн токенов и 3 живых хода.
