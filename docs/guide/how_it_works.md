# Как работает ход агента — по шагам

Пример: пользователь спрашивает в консоли «Что EIA прогнозирует по Brent до конца 2026 года и какие свежие события
могут изменить прогноз?».

## 1. Консоль ставит задачу агенту

`agent.py` собирает текст задачи и отправляет его `POST /api/tasks` в Ouroboros. Ход консоль читает из
штатного потока событий задачи (`GET /api/tasks/{id}/events`, SSE): вызовы инструментов, раунды LLM, итог.

| Что в тексте задачи | Зачем |
|---|---|
| последние реплики разговора — проверенные черновики со ссылками `[R#]` | местоимения («а что по WTI?») и повторное использование доказательств |
| вопрос | экранирован: текст с «/» в начале не станет командой Ouroboros (`/panic`, `/evolve`) |
| «Язык ответа: русский» | ~30 тыс. токенов английского системного контекста Ouroboros тянут к английскому |
| правила хода консоли | только отличия от регламента (`TURN_RULES` в `agent.py`): напоминание, что вопрос вне компетенции — только отказ, без инструментов; `verify_answer` с `render=false`, а в `finish_task` — проверенный черновик со ссылками символ в символ (метки и список источников добавит консоль); не писать в память и не запускать фоновых задач. Сам протокол — в регламенте (одна точка правды). Текст задачи — в стабильной части промпта (на профиле openrouter у моделей `anthropic/*` — под кэшем), поле `context` задачи — в динамической части |
| `oilo-turn <id>` | служебная метка в конце текста задачи: журнал LLM-шлюза относит каждый вызов модели к этому ходу (такая же строка в вопросе пользователя обезвреживается) |

Параметры задачи:
- `disabled_tools` — 137 встроенных инструментов Ouroboros (код, shell, git, браузер, память, фоновые задачи);
- `memory_mode=forked` — запись в копию памяти задачи: ходы консоли память агента не меняют. Читает задача при этом
  общую память, в том числе разговор владельца в комнате Main: штатного рычага нет.

## 2. Ouroboros видит роль и инструменты

Контекст каждого раунда собирает Ouroboros.

| Часть контекста | Откуда | Можно ли менять |
|---|---|---|
| SYSTEM.md + BIBLE.md (~22 тыс. токенов) | образ Ouroboros | нет: это ядро; на профиле openrouter (модели `anthropic/*`) цену держит кэш промпта, на GigaChat Freemium — $0, расход в токенах |
| identity.md — «моя работа — анализ нефтегазового рынка» | засев `ouroboros/memory/identity.md` | да: агент может переписать штатно, с журналом |
| knowledge/overview.md — регламент аналитика («Shared understanding») | засев `ouroboros/memory/knowledge/overview.md` | да: точка самоулучшения |
| WORLD.md — среда (инструменты, сеть, пользователи) | засев `ouroboros/memory/WORLD.md` | да |
| схемы 12 инструментов: 9 `mcp_oil__*` + finish_task, knowledge_read, knowledge_list | MCP-сервер tools + Ouroboros | MCP — в коде tools |

## 3. Агент зовёт `research` — граф LangGraph

`graphs/research.py`, каждый узел пишется в трейс (`graphs/runs.py`):

1. **plan** (LLM субагента): запросы к отчётам на английском и русском, агентства, выпуски, нужна ли свежесть.
   Здесь «свежие события» → `needs_freshness`.
2. **retrieve** (код): BGE-M3 dense + sparse в Qdrant, все запросы одной пачкой → RRF (оценки фрагмента по запросам
   складываются) → надбавка последнему выпуску → 16 кандидатов. Фрагмент таблицы начинается с её подписи.
3. **select_grade** (LLM субагента, один вызов):
   - выбирает до 6 полезных фрагментов (listwise, вместо cross-encoder на CPU); видит каждый фрагмент целиком и его
     раздел или подпись таблицы;
   - оценивает, хватает ли отчётов: `sufficient` / `partial` / `insufficient`.
4. **route** (код, `config/current/web.yaml`): веб нужен, если требуется свежесть, отчётов мало или есть разрыв по
   датам. Это правило приоритета источников (Р4). Решение и его причины пишутся в журнал решений пакета.
5. **web** (код): сначала домены уровней 0–1, затем открытый поиск без deny-списка. Каждый домен получает уровень
   доверия 0–3; жёлтая пресса отсекается до контекста.
6. **pack**: каждое доказательство получает устойчивый id в журнале доказательств — `[R#]` отчёт, `[W#]` веб.
   Агенту уходит текст пакета: фрагменты с метками, оценка достаточности, решение о вебе.

Прогноз, сценарий, история цен и текущие котировки — граф `graphs/calc.py`. Расчёт получает id `[F#]`, его JSON
(медиана, интервалы, скилл; у котировки — сорт, единица, контракт, цена, время сделки и спот EIA) хранится в журнале.
Вопрос «сколько сейчас стоит Brent / WTI / газ Henry Hub / TTF» агент отправляет сразу в `price_quote(benchmark)` —
без `research`.

## 4. Черновик и проверка

Агент пишет черновик в формате «Кратко → Детали → Неопределённость». В конце каждого предложения с цифрой стоит id
источника. Затем вызывает `verify_answer` (граф `graphs/verify_answer.py`: resolve → check → render; сверка цифр —
`evidence/verify.py`) и передаёт в `pack_ids` номера пакетов P# своего хода:
- каждое число ищется в тексте процитированного источника **из журнала**, а не из ответа модели. Учитываются
  десятичная запятая, округление и масштаб kb/d ↔ mb/d. «Выросли на 1,9» не подтверждается «fell by 1.9»;
- неизвестная ссылка, ссылка не из пакетов этого хода (id из соседней задачи или из памяти), цифра без источника и
  цифра только из веба уровня 3 — жёсткие замечания. С ними агент правит черновик и проверяет снова — пока
  `verify_answer` не скажет, что проверок больше не будет (`verify.max_checks` = 2, счёт — по пакетам хода). После
  последней он велит завершать без новой проверки;
- если число есть в другом надёжном источнике хода, ссылка дописывается автоматически (CiteFix);
- собственный расчёт агента (разница, сумма, отношение, изменение в %) помечается «(расчёт)». Код воспроизводит
  его из уже подтверждённых цифр этого и двух предыдущих предложений; выдуманное «расчётное» число не пройдёт;
- кириллические «Р»/«Ф» в ссылках (`[Р12]`) приводятся к латинским id журнала;
- номера страниц и таблиц («с. 33, 44») — не цифры данных. Свой раздел «Источники» в конце черновика проверка
  отбрасывает: список источников ставит система, а список агента его дублировал бы.

## 5. Финал и что видит пользователь

Агент завершает ход отдельным шагом, когда прочитал результат проверки:
`finish_task(answer=<проверенный черновик со ссылками>)`. В одной пачке с `verify_answer` Ouroboros завершение не
принимает (`unobserved_tool_results`). Если Ouroboros не закрыл задачу через 30 с после `finish_task`, ход закрывает
консоль (метка «завершён консолью»). Пауза по потолку денег на задачу тоже закрывает ход сразу.

Что увидит пользователь, решает сервис инструментов — там журнал доказательств и проверка. Консоль отправляет ответ
агента и номера прогонов (`trace`) его инструментов в `POST /api/finalize` (`graphs/verify_answer.finalize`):
1. Доказательства **этого хода** — те, что выдали пакеты его прогонов, плюс ссылки из истории разговора.
2. Показываемый текст проверяется ещё раз только по ним. Ссылка на чужой ход — ошибка; в тексте она показывается как
   «источник не найден», а не меткой чужого источника.
3. Код ставит метки:
   - `[Отчёт EIA STEO, октябрь 2026, с. 6]`;
   - `[Источник: reuters.com, web, 2026-10-18, уровень 1]`;
   - `[Расчёт: прогноз Brent на 3 мес., данные EIA по 2026-10-14]`;

   а ещё список источников и строку «Проверка: N/M цифр подтверждены» (`graphs/render.py`). Ответу на английский
   вопрос — английские метки и подвал: `[Report EIA STEO, October 2026, p. 6]`, `[Source: reuters.com, web, …,
   tier 1]`, «Sources».
4. Источник показанного текста — `answer_source`:
   - `verified_draft` — ответ = проверенный черновик (или его текст для показа — узнаётся);
   - `reverified_final` — показан текст агента, отличный от проверенных черновиков (или черновиков не было): он
     проверен заново, итог — в проверке хода; непройденной она остаётся, только если откатиться не на что;
   - `fallback_verified_draft` — агент не завершил (таймаут, пауза) или его правка не прошла проверку: показан
     последний проверенный черновик;
   - `unverified` — показывать нечего: пустой ответ без проверенных черновиков.

Консоль записывает ход (`console/turns.py`): что показано, вызовы инструментов с их прогонами, деньги, время и
онлайн-проверки.

Вне консоли — в UI Ouroboros, Telegram и утренней сводке — финала хода нет. Там те же метки, список источников и
строку проверки ставит сам `verify_answer` (по умолчанию `render=true`), и агент завершает ответ его «текстом для
показа». Ход консоли просит `render=false`.

## 6. Что остаётся для мониторинга

| Источник | Что в нём |
|---|---|
| Ouroboros поток событий `/api/tasks/{id}/events` | раунды (модель, токены, кэш, $), вызовы инструментов с аргументами и началом результата (`trace …`) |
| tools `/api/runs/{trace}` | узлы графа, LLM субагентов с промптами, решения, проверка |
| gateway `/ledger?turn=`, `/calls/{id}` | каждый вызов LLM хода с ценой (профиль openrouter — фактическая `usage.cost` OpenRouter, GigaChat Freemium — $0 и токены) и телом запроса (что модель видела) |
| консоль `turns.sqlite` | ход целиком + онлайн-проверки + отпечаток версии агента |

Подробно — вкладки консоли «Ходы» и «Мониторинг».
