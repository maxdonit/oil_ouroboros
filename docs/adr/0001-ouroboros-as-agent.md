# ADR-0001. Агент — Ouroboros, его инструменты — субагенты LangGraph по MCP

- Статус: принято
- Контекст:
  - Требования ([docs/requirements.md](../requirements.md)): основа агента — Ouroboros; Т2 — «Фреймворк агента:
    LangChain, LangGraph».
  - Цель проекта: агент на Ouroboros, все его инструменты — RAG, веб, прогноз, проверка, субагенты — на LangGraph;
    параметры видны и версионированы, чтобы агент мог улучшаться под замером.

## Решение

| Слой | Чем сделан | Что делает |
|---|---|---|
| Агент | Ouroboros v7.7.0 (официальный образ, без форка, закреплённый коммит e41596c) | Ведёт диалог, планирует, решает, какие инструменты и в каком порядке звать, пишет ответ |
| Инструменты | Графы LangGraph (сервис tools) по MCP | research (отчёты → достаточность → веб по политике), search_reports, search_web, прогноз, сценарий, история цен, текущие котировки (price_quote), проверка ответа; справка о составе базы list_reports — обычная функция, не граф |
| Приоритет источников (Р4) и проверка цифр | Код внутри графов | Приоритет «сначала отчёты» — узел-маршрутизатор `route_after_grade` по web.yaml. Цифры сверяет `verify` с текстами журнала доказательств |
| Финальный ответ | Сервис инструментов (финал хода, `POST /api/finalize`) | Перепроверяет показываемый текст по доказательствам хода. Метки источников и строку проверки ставит код, не модель; консоль показывает и записывает ход |

Соответствие Т2 формулируется честно:
- **функции агента — графы LangGraph на langchain-core:** RAG, веб-поиск с фильтром, приоритет источников,
  расчётный модуль, проверка цифр, субагенты;
- **оркестратор диалога — Ouroboros:** это основа агента по требованиям и решение заказчика;
- **отличие от буквы Т2:** верхний цикл рассуждения — не LangGraph.

## Риски выбора и меры

| Риск | Мера (сверено с кодом Ouroboros v7.7.0) |
|---|---|
| Личность и конституция Ouroboros: «not an assistant» | Роль — штатные средства памяти: `identity.md` (самоописание от первого лица: «моя работа — анализ рынка»), регламент `knowledge/overview.md` (всегда в контексте как «Shared understanding»), правила хода в тексте задачи. Контроль на eval: метрики persona_clean и answer_is_checked_text |
| Большой контекст на каждый раунд | В ходах консоли 137 из 140 встроенных инструментов отключены (`disabled_tools`), режим контекста low, LLM-проверка безопасности на каждый вызов и ревью задачи выключены. Остаётся неизменяемое ядро: SYSTEM.md + BIBLE.md ~22 тыс. токенов, с картами архитектуры ~29 тыс.; на профиле openrouter (модели `anthropic/*`) его держит кэш промпта: шлюз возвращает маркеры Anthropic `cache_control`, которые Ouroboros снимает на маршруте `openai-compatible::`, и раунд после первого читает ~60 тыс. токенов из кэша по 0,1 цены. На GigaChat Freemium (профиль по умолчанию) вызовы бесплатны, расход — в токенах |
| Ouroboros — агент одного владельца | Ход — отдельная задача API с `memory_mode=forked`: разговоры разных пользователей не смешиваются. Историю разговора хранит консоль и передаёт в тексте задачи |
| В Ouroboros нет RAG, цитат, прогноза | Это и есть инструменты LangGraph. Ouroboros для MCP-результатов — «недоверенные данные», поэтому правила поведения — в памяти агента, а не в описаниях инструментов |
| Модель подгоняет цитаты задним числом | Модель пишет только id доказательств. Тексты источников — в журнале доказательств, вне досягаемости модели. Каждую цифру сверяет код, а что показать пользователю консоли, решает финал хода в сервисе инструментов |

## Два входа: пользователи — консоль, владелец — Ouroboros как есть

- **Пользователи — через задачи `POST /api/tasks`, а не через WebSocket-чат.** Кадры чата рассылаются всем
  клиентам, в чате нельзя отключить инструменты, а ход пользователя должен идти с проверкой цифр и копией памяти.
- **Владелец — через собственный UI Ouroboros и Telegram** (профиль `owner`): там Ouroboros как есть, со всеми его
  инструментами. Настройки и риски этого канала — [owner.md](../guide/owner.md).
- **Роль — в памяти, а не в навыке.** Регламент в памяти виден агенту всегда и меняется штатным `knowledge_write`
  с журналом. Навык агент читает по своему решению.

## Последствия

- Каждый ответ стоит раундов основной модели Ouroboros, ~60 тыс. входных токенов на раунд (на профиле openrouter — в
  основном из кэша промпта). Цена хода — в журнале шлюза по метке хода.
- Версия агента — отпечаток памяти, настроек, шаблона хода, MCP-инструментов, каталога параметров и базы
  отчётов: по ней мониторинг и eval сравнивают изменения.
- Обновление Ouroboros — только сменой закреплённого коммита, с прогоном eval.
